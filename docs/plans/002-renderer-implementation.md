# Better Markdown Preview Implementation Plan

## Objective

Turn the product-empty foundation into Better Markdown Preview: an extension
that augments VS Code's built-in Markdown preview with full GFM authoring
behavior, Airplan-derived document layout and table of contents, selected
jimeh.me Markdown affordances, local Mermaid rendering, and richer fenced-code
presentation while preserving native highlighting and the active VS Code theme.

Canonical references:

- [VS Code Markdown extension guide](https://code.visualstudio.com/api/extension-guides/markdown-extension)
- [Airplan Markdown rendering contract](https://github.com/jimeh/airplan/blob/main/SPEC.md#3-markdown-rendering)
- [jimeh.me Markdown configuration](https://github.com/jimeh/jimeh.me/blob/main/astro.config.ts)

## Architectural Constraints

- Extend the built-in preview through `markdown.markdownItPlugins`,
  `markdown.previewStyles`, and `markdown.previewScripts`; do not create a
  replacement webview.
- Preserve native source synchronization, heading IDs, link/image resolution,
  workspace-trust behavior, preview security settings, code-copy controls, and
  user `markdown.styles` precedence.
- Keep VS Code's native Highlight.js rendering so syntax colors follow the
  active editor token theme. Do not add Shiki.
- Wrap existing Markdown-It rules instead of assuming this extension is the
  only contributor. Preserve compatible earlier and later plugin behavior.
- Keep extension-host code browser-safe and continue producing desktop and web
  bundles.
- Scope every owned class and data attribute with `better-markdown-preview` or
  `bmp` to avoid collisions.
- Use VS Code `--vscode-*` colors and light, dark, and high-contrast body
  classes. Do not add a separate theme toggle or fixed page palette.
- Bundle Mermaid locally. Do not load executable code, fonts, icons, or styles
  from a CDN.
- Keep readable, escaped Mermaid source visible until rendering succeeds and
  after any load or render failure. Use Mermaid's strict security mode.
- Keep preview enhancement initialization idempotent across VS Code content
  replacement and theme changes.
- Add dependencies only when they replace material parser work; implement
  narrow Airplan-specific syntax locally.

## Rendering Contract

### GFM and Markdown Extensions

- Preserve CommonMark and the native raw-HTML behavior.
- Provide complete GFM-visible behavior: tables, strikethrough, task lists,
  extended URL/email autolinks with balanced punctuation, and GFM tag filtering.
  This behavior must not silently depend on `markdown.preview.linkify` being
  enabled.
- Add definition lists and footnotes.
- Add GitHub alerts `NOTE`, `TIP`, `IMPORTANT`, `WARNING`, and `CAUTION`.
  Alerts may contain normal block Markdown. Unknown markers remain ordinary
  blockquotes.
- Preserve existing heading IDs and source-map attributes generated by VS Code.

### Frontmatter

- Preserve VS Code's native YAML frontmatter recognition.
- Recognize TOML frontmatter only at document byte zero, after an optional UTF-8
  BOM, with exact matching `+++` delimiter lines.
- Render recognized frontmatter as a collapsed native details block containing
  its escaped original text. Exclude it from headings and the TOC.
- In an interactive preview, malformed or unclosed frontmatter remains ordinary
  Markdown instead of making the complete preview fail.

### Responsive Columns

Implement Airplan's narrow Pandoc fenced-div subset:

- An outer delimiter is at least four colons followed only by `{.columns}`.
- It contains at least two direct child divs using a shorter delimiter of at
  least three colons and `{.column}` with an optional `width=N%` attribute.
- Widths accept integer or decimal percentages greater than zero and at most
  100. Unweighted columns share space equally.
- Normal block Markdown works inside each direct child.
- Unknown attributes, invalid widths, nesting, one-child containers,
  orphaned/unterminated delimiters, and malformed structures remain ordinary
  Markdown without partial transformation.
- Columns prevent overflow and stack at narrow viewport and print widths.

### Mermaid

- Only an exact lowercase `mermaid` fence is a diagram. `Mermaid`,
  `mermaid-js`, and extra info remain ordinary highlighted code.
- Emit escaped source fallback without a nested `<code>` wrapper that would
  trigger the native code-copy presentation.
- Load the locally bundled Mermaid module only when a diagram exists.
- Render explicitly with strict security and colors derived from the current
  VS Code theme variables.
- Re-render after a VS Code theme-class change. Print and high-contrast output
  must remain legible.
- A missing asset, CSP/import failure, invalid diagram, or Mermaid exception
  leaves source visible and marks the block as failed without breaking other
  preview enhancements.

### Rich Fenced Code

Support the useful jimeh.me fence metadata while retaining the native highlighter:

- `title="path/to/file"`
- line ranges such as `{1,3-5}`
- literal word emphasis such as `/needle/`
- `showLineNumbers`
- `[!code ++]` and `[!code --]` annotations on changed lines

The Markdown-It fence wrapper must delegate syntax highlighting to the existing
renderer, strip only recognized metadata/annotations, escape metadata used in
HTML, and preserve native language classes and source mapping. The preview
script may split highlighted DOM into visual lines, but line numbers must be
CSS-only and copied code must remain the authored code without annotation
markers. Do not add a second copy button.

Malformed or unsupported fence metadata remains harmless and must not turn a
code block into executable HTML.

## Presentation Contract

- Base the composition on Airplan's clean page: centered shell around 54rem,
  prose measure around 78ch, comfortable line height, restrained borders and
  surfaces, and wider code/tables/media where useful.
- Use a three-column wide layout so the document remains centered while a
  sticky H1-H3 TOC occupies the left rail.
- Omit a leading document-title H1 from the TOC and hide the TOC with fewer
  than two remaining entries.
- Highlight the active heading with requestAnimationFrame-throttled scroll
  tracking.
- At narrow widths, move the TOC inline above the document. Once that inline
  TOC scrolls away, expose a compact accessible floating control/dialog.
- Restore focus after closing the TOC dialog; support Escape, outside click,
  keyboard navigation, and reduced motion.
- Style tables, task lists, alerts, frontmatter, footnotes, definition lists,
  columns, code metadata, Mermaid fallback, images, and blockquotes.
- Use `overflow-wrap`, constrained media, and scrollable code/tables to prevent
  horizontal page overflow.
- Preserve focus visibility and high-contrast borders.
- Do not port Airplan's toolbar, source/download/raw controls, independent theme
  selector, or transition suppression. Do not port blog-only MDX media,
  Fancybox, or external-link icons.

## Expected Scope

- Extension activation and Markdown-It composition under `src/`.
- Narrow parser/renderer modules for GFM gaps, alerts/frontmatter, columns,
  Mermaid fences, and code metadata.
- Preview runtime modules for lifecycle, TOC, code presentation, and Mermaid.
- Theme-aware preview CSS.
- Esbuild targets for extension hosts and preview assets, including a
  conditionally imported local Mermaid bundle.
- Manifest contributions and exact VSIX inventory updates.
- Kitchen-sink and focused Markdown fixtures.
- Unit, DOM, Extension Host, web-host where stable, package, and browser/runtime
  evidence described below.
- README, changelog, architecture, testing, and agent-map updates matching the
  actual feature.

## Non-goals

- A custom Markdown editor or custom webview.
- Exact GitHub HTML byte parity; observable GFM behavior is the contract.
- Repository issue/commit-reference linkification.
- Inline-code language annotations such as ``code{:js}``.
- Shiki or a selectable syntax-highlighting backend.
- User settings for individually disabling features in the first release.
- Marketplace publication, release automation, or release creation.
- Replacing VS Code's Markdown language service, outline, or editor commands.

## Focused and Final Gates

- Parser/unit loop: `pnpm test -- <focused files>` or the repository's resulting
  named focused task.
- DOM loop: dedicated preview-runtime test task.
- Fast handoff: `mise run check`.
- Extension integration: `mise run test:extension` and the web-host task if
  added.
- Artifact: `mise run package:validate`.
- Workflow: `mise run ci:workflows`.
- Intended-final-head local gate: `mise run verify`.
- Final clean-environment gate: required GitHub Actions checks on the exact
  pushed head.

## Risks

- Markdown-It contributor ordering can cause renderer wrappers to overwrite one
  another. Tests must install sentinel rules before this extension and prove
  delegation.
- DOM rewriting can break native code copying or source synchronization. Keep
  `data-line` elements intact and assert copied text/source-map attributes.
- Conditional Mermaid loading may conflict with the preview CSP. Verify it in a
  real VS Code preview; if the current supported hook cannot load a local chunk
  conditionally, prefer a documented local always-loaded asset over any CDN.
- Mermaid is a large dependency. Keep it out of the extension-host bundles and
  verify package contents and bundle sizes.
- VS Code replaces preview body content without recreating the webview. A
  one-shot `DOMContentLoaded` handler is insufficient.
- User styles load after contributed styles. The layout must degrade safely when
  users override it rather than assuming exclusive CSS ownership.
- Web-host and Electron automation can be environment-sensitive. Do not claim a
  supported runtime from build success alone; record the exact runtime evidence
  and any residual platform limitation.

## Evidence Ownership

- Implementer: test-first failures, focused parser/DOM/integration execution,
  runtime evidence, and completed closure matrix.
- Orchestrator: implementation inspection, evidence sufficiency, and only
  missing or invalidated checks.
- Codex and Claude reviewers: independent requirement, security, lifecycle,
  compatibility, and test-quality reasoning.
- CodeRabbit: external PR review after internal acceptance.
- CI: clean-environment final-head verification.
